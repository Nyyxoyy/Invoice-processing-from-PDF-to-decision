# Invoice desk — AP invoice decisioning

Vendor invoice PDF in, explained accounts-payable decision out. The model only reads the document; code verifies every value, decides all money, and explains itself. Two roles: invoice reviewer (approves) and procurement admin (suppliers, purchase orders, requests).

- Plan: `PLAN.md` · Implementation record: `IMPLEMENTATION.md` · UX audit: `UX_FINDINGS.md`
- Run locally: `python -m venv venv && venv/bin/pip install -r backend/requirements.txt`, put `GEMINI_API_KEY` in `.env`, then `venv/bin/python -m uvicorn app.main:app --port 8321 --app-dir backend` and open http://localhost:8321. No sign-in: the reviewer workspace opens directly and the top bar switches to procurement.
- Tests: `venv/bin/python -m pytest backend/tests -q`
- Edge cases (faulty and non-invoice PDFs): the **Edge cases** tab in the app, generated from `backend/app/edge_cases.py`. Every row carries the saved result of a real run — open it from the tab to see the decision, reason codes, document-type verdict, the fields the reader returned and the activity trail, with nothing re-processed. Evidence lives in `evidence/edge-cases/` (`fixtures/` the uploaded files, `runs/` the saved results, `results.json` the index) and `EDGE_CASES_VERIFIED.md` is the same thing as a report. Re-verify with `venv/bin/python tools/edge_case_probe.py` (`--only <case-id>` for single cases, `PROBE_CALL_INTERVAL` to pace the reader).
- Deploy: `Dockerfile` + `render.yaml` (Render free tier; set `GEMINI_API_KEY` in the dashboard). On the free tier the workspace resets to its seeded state after inactivity.

AI-first workflow: upload a PDF to extract fields, validate supplier and PO matches, and approve eligible invoices automatically. The AI dashboard shows invoice status plus High (90–100), Medium (70–89), or Low (0–69) confidence; low-confidence held invoices appear first. Scores combine verified fields (40), supplier (20), PO (25), totals (10), and currency (5), with critical-uncertainty caps. These are evidence scores, not model probabilities, and never override financial rules.

New uploads automatically create a procurement ticket when a verified supplier is absent or an order reference is missing from the register. Supplier onboarding includes the order requirement in one ticket; extraction uncertainty stays with the reviewer. Tickets include extracted details and the `invoice-ai` actor in the audit trail. Authorized supplier / PO creation remains procurement’s responsibility. Existing invoices receive confidence on read; old uploads are not retroactively sent to procurement.

Bulk intake: drop several PDFs or a ZIP of PDFs (25 documents per batch) and follow the batch page; the sample library (`fixtures/pdfs`, regenerate with `venv/bin/python tools/make_samples.py`) covers every outcome the desk produces. No-upload intake: drop files into the watched folder (`data/intake`, syncable from Drive/Dropbox/SFTP/gcsfuse), paste public or Drive "anyone with the link" URLs, or connect an IMAP mailbox; Google Drive/Cloud Storage connect with a service account (`backend/app/connectors.py`, `sources.py`).

The recommended onboarding dataset is `reviewer-starter-kit.zip` (seven PDFs): two automatic approvals, two procurement requests, two low-confidence reviews, and a non-invoice rejection. Individual PDFs remain available. `fixtures/reviewer-demo.json` holds the curated descriptions and reviewer next steps; the broader edge-case library remains separate. Regenerate with `tools/make_reviewer_demo.py` using Python with ReportLab installed. The Harbor and Cedar demo suppliers and PO-7101 / PO-7102 are seeded additively on startup, without overwriting procurement edits. Intended outcomes assume the PDFs have not already been processed and these demo records have not been changed.
